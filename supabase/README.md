# Supabase для Winter Arc v0.2

## Как применить схему

1. Открой проект в [Supabase Dashboard](https://supabase.com/dashboard) → **SQL Editor** → **New query**.
2. Вставь целиком `supabase/schema.sql` и нажми **Run**. Должно закончиться `Success. No rows returned`.
3. Повторный запуск безопасен (всё через `if not exists` / `drop policy if exists` / `create or replace`).
4. Проверь: **Authentication → Sign In / Providers → Email**: «Confirm email» выключено, минимальная длина пароля 8.
5. **Database → Publications → supabase_realtime**: должны быть `feed_events`, `reactions`, `nudges`, `public_stats`.
6. **Storage**: появился приватный бакет `checks` (только JPEG, до 1 МБ).
7. **Realtime → Settings**: «Allow public access» оставь включённым — им пользуется пинг синхронизации между твоими устройствами (сообщение без данных, только «я обновился»). Если выключишь, синхронизация всё равно работает: при открытии приложения и раз в 2 минуты.

Логин — синтетический e-mail `<ник>@winter-arc.invalid` (зарезервированный домен, письма туда не уходят никогда). Профиль можно создать только с ником, совпадающим с логином.

## Что где

| Таблица / RPC | Кто видит / пишет |
|---|---|
| `profiles` | я + участники моих пати; создаю/меняю только свой (`display_name`, `avatar`) |
| `parties`, `party_members` | только участники; изменения только через RPC |
| `create_party(name)`, `join_party(code)`, `leave_party(id)`, `regenerate_party_code(id)` | RPC; максимум 8 человек в пати, 3 пати на человека, 10 неверных кодов в час |
| `public_stats` | пишу свою, читают участники моих пати; < 32 КБ |
| `feed_events` | пишу свои только в свои пати, читают участники, удаляю свои; дедупликация по `(party_id, user_id, key)` |
| `reactions` | участники пати события |
| `nudges` + `send_nudge(to, kind)` | читают отправитель и получатель; получатель ставит `seen_at`; 1 пинок в час на пару |
| `private_state` | только владелец; < 2 МБ; запись с проверкой `rev` (compare-and-swap) |
| `delete_my_account()` | отдаёт пати старейшему участнику (пустые удаляет), удаляет пользователя, остальное каскадом |
| бакет `checks` | путь `{party_id}/{user_id}/{week}.jpg`; загрузка в свою папку, если состоишь в пати; читают участники |

## Ручная проверка (после применения схемы)

Нужны два браузера/устройства (A и B), например телефон и Мак или обычное и приватное окно.

**Аккаунт**
- [ ] A: «Пати» → «Новый аккаунт», ник `test_a`, пароль 8+ символов → вход без почты, видно «Создать пати / Вступить».
- [ ] Повтор регистрации с тем же ником → «Этот ник уже занят».
- [ ] «Уже есть» с неверным паролем → «Неверный ник или пароль».
- [ ] Пароль из 7 символов → «Минимум 8 символов».

**Пати**
- [ ] A: «Создать пати» → виден код вида `SNOW-4821`, «Копировать», на телефоне «Поделиться».
- [ ] B (аккаунт `test_b`): «Вступить по коду» с кодом в нижнем регистре и без дефиса → вступил; у A в ленте «Вступил в пати» без перезагрузки.
- [ ] Неверный код → «Такого кода нет»; 10 неверных подряд → «Слишком много неверных кодов».
- [ ] Карточки участников: уровень, HP, гирлянда дня, «X из 7», честность, босс. Отметь квест у B → у A через ~5 с меняется гирлянда.
- [ ] A: «Пнуть» B → у B баннер сверху и цифра на вкладке «Пати»; повторный пинок → «Его уже пинали за последний час».
- [ ] B: «Слился» (рилсы, любая причина, заметка «секрет») → у A в ленте «Слился на рилсах», без причины и заметки. Камбэк → «→ камбэк ✅».
- [ ] Реакции 🫡🔥❄️💪 ставятся/снимаются, видны второму без перезагрузки.
- [ ] «Ещё → Аккаунт»: выключи «Срывы и камбэки» → новый срыв в ленту не попадает.
- [ ] Недельный обзор → «Воскресная сверка» → загрузить скрин → в ленте превью, по тапу полный размер.
- [ ] Owner: «Сменить» код → старый код не работает.
- [ ] «Выйти из пати» у B → у A участник пропал, события B из ленты исчезли.
- [ ] Девятый участник → «В пати уже 8 человек».

**Синхронизация**
- [ ] Один аккаунт на A и B. На A отметь квест и добавь задачу → на B после открытия/фокуса (или через пинг за пару секунд) всё появилось.
- [ ] Офлайн на обоих: A отмечает квест X, B — квест Y того же дня; включи сеть → на обоих оба квеста.
- [ ] Одну задачу переименовать на обоих офлайн → побеждает более позднее, а на проигравшем устройстве в «Ещё → Аккаунт → Снимки» появился снимок «Перед слиянием…»; «Вернуть» работает.
- [ ] Удали покупку на A → исчезла на B.
- [ ] Новое устройство: на онбординге «Уже играю на другом устройстве — войти» → данные подтянулись, онбординг пропал.
- [ ] Тема и снег у устройств свои и не синхронизируются.

**Безопасность (SQL Editor, роль authenticated не нужна — проверяем снаружи)**
- [ ] Без входа: `curl "$URL/rest/v1/profiles" -H "apikey: $KEY"` → пустой ответ/ошибка доступа, не данные.
- [ ] Пользователь C вне пати не видит профили, статистику, ленту и скрины A/B.
- [ ] `insert into party_members` с клиента → запрещено.

**Удаление**
- [ ] «Ещё → Аккаунт → Удалить аккаунт» → вход с этим ником больше не работает, пати осталась у других, локальные данные на устройстве целы.
